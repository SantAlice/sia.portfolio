# Аватар в шапке — дорожка v7

Заменяет v6. Логика та же (дуга + возврат в нейтраль), меняются три вещи:
**цвет фона**, **частота кадров** и **сглаживание в JS**. Значения из v6 не подойдут —
в дорожке теперь 423 кадра вместо 213, поэтому `MAP` пересчитан.

Проект — статический сайт (`index.html`, `css/`, `js/`), не React.

---

## Что изменилось

1. **Фон видео перекрашен в `#3D84A8`** — это `--blue`, основной цвет сайта.
   Раньше видео было светлее шапки, и был виден прямоугольник.
   Теперь `--hero-bg` должен быть равен `--blue`, а не отдельным цветом.
2. **48 кадров в секунду вместо 24.** Кадры между исходными достроены
   интерполяцией движения, шаг поворота головы стал вдвое мельче.
   Это главное, что даёт плавность при медленном движении мыши.
3. **Сглаживание в JS привязано к реальному времени кадра,** а не к его номеру.
   На 120-герцовом мониторе движение теперь такое же, как на 60-герцовом.
   Плюс убраны лишние перемотки: `currentTime` не трогается, пока
   голова стоит на месте.

## Про подключение видео

Видео должно подключаться обычной ссылкой на файл в `public/`.
**Не вшивать его в HTML как `data:` URI** — это 6 МБ base64 внутри разметки,
страница не отрисуется, пока они не скачаются и не распарсятся, и браузер
не сможет их закешировать. Если сборка почему-то требует инлайна, единственный
рабочий вариант — перевести `data:` в `blob:` до старта скрипта аватара.

## Состояние покоя

`avatar-poster-v7.jpg` — ровно первый кадр дорожки: фронтальная нейтральная поза,
взгляд в камеру. До первого движения мыши постер и первый кадр видео совпадают
пиксель в пиксель.

---

## Как это работает

Дорожка: нейтраль → вверх-вправо → вправо → вниз-вправо → вниз → вниз-влево →
влево → вверх-влево → обратно в нейтраль.

Покрытая дуга — **от 315° через 0° до 245°**, где 0 вправо, 90 вниз, 180 влево,
270 вверх. Не покрыт сектор **245°–315°** — верх.

В непокрытом секторе взгляд возвращается в нейтраль, причём по настоящим кадрам
исходника: из левого края дуги — через кадры 334–422, из правого — через 48–0
в обратную сторону.

Расположение: **аватар справа, текст слева.**

Секция, в которой лежит аватар, обязана иметь фон `--hero-bg` на всю ширину
блока с видео. Если видео стоит на участке с другим фоном — будет виден
прямоугольник, как было в прошлой версии.

**Про цвет отдельно.** Браузер декодирует видео из YUV, и точного совпадения
с CSS-цветом там не бывает само по себе — из-за этого прямоугольник и был виден.
Поэтому фон внутри mp4 записан не ровно `#3D84A8`, а на пару единиц синее,
и файл размечен как BT.709 / limited range. После декодирования браузер рисует
ровно `#3D84A8`. Проверено измерением пикселей на живой странице: фон страницы
и фон видео сходятся с точностью до единицы.

Из этого следуют две вещи:

- **менять `--hero-bg` нельзя** — под другой цвет фон в видео надо перезаписывать,
  подгонкой CSS это не лечится;
- **пережимать mp4 нельзя** — перекодирование без этих же флагов сдвинет цвет
  и вернёт прямоугольник.

## JS

```js
(function () {
  var box = document.getElementById('avatarBox');
  var video = document.getElementById('avatarVideo');
  if (!box || !video) return;

  var DURATION = 8.8125;   // длительность дорожки, секунды
  var EASE = 0.1;          // доля пути за кадр при 60 Гц; меньше — ленивее
  var AR = 720 / 1076;     // пропорция видео
  var STEP = 1 / 96;       // половина кадра при 48 fps

  // Покрытая дуга: направление взгляда -> позиция на дорожке 0..1.
  // Градусы экранные: 0 вправо, 90 вниз, 180 влево, 270 вверх.
  // Дуга проходит через 0°, поэтому углы развёрнуты в непрерывную
  // шкалу 315..605 (605 = 245 + 360). Значения сняты покадрово —
  // скорость движения по дуге неравномерная. Формулой не выводится.
  var MAP = [
    [ 315.0, 0.1147 ], [ 328.0, 0.1430 ], [ 336.0, 0.1572 ],
    [ 342.0, 0.1714 ], [ 350.0, 0.1856 ], [ 358.0, 0.1998 ],
    [ 361.0, 0.2092 ], [ 378.0, 0.2565 ], [ 384.0, 0.2707 ],
    [ 392.0, 0.2849 ], [ 405.0, 0.3132 ], [ 415.0, 0.3416 ],
    [ 425.0, 0.3700 ], [ 437.0, 0.3983 ], [ 448.0, 0.4267 ],
    [ 456.0, 0.4551 ], [ 463.0, 0.4882 ], [ 468.0, 0.5496 ],
    [ 468.5, 0.5544 ], [ 490.0, 0.5733 ], [ 505.0, 0.5969 ],
    [ 532.0, 0.6158 ], [ 548.0, 0.6395 ], [ 560.0, 0.6631 ],
    [ 574.0, 0.6868 ], [ 584.0, 0.7104 ], [ 593.0, 0.7293 ],
    [ 600.0, 0.7530 ], [ 605.0, 0.7861 ]
  ];

  var ARC_LO = 313;        // начало дуги — взгляд вверх-вправо
  var ARC_HI = 605;        // конец дуги — взгляд вверх-влево (245° + 360)
  var NEUTRAL = 0.0;       // фронтальная поза, первый кадр дорожки

  function angleToPos(deg) {
    // разворачиваем в непрерывную шкалу: дуга идёт через 0°
    var u = deg % 360;
    if (u < 0) u += 360;
    if (u < 245) u += 360;

    if (u >= ARC_LO && u <= ARC_HI) {
      for (var i = 0; i < MAP.length - 1; i++) {
        var a = MAP[i], b = MAP[i + 1];
        if (u >= a[0] && u <= b[0]) {
          return a[1] + (b[1] - a[1]) * ((u - a[0]) / (b[0] - a[0]));
        }
      }
      return MAP[0][1];    // 313..315 — самый край дуги
    }
    // сектор 245..313 — верх, в дорожке его нет: идём в нейтраль.
    // К какому её краю — решает кратчайшая дуга в loop(),
    // поэтому голова возвращается той же стороной, откуда пришла.
    return NEUTRAL;
  }

  // точка отсчёта — глаза персонажа внутри РЕАЛЬНОЙ области видео,
  // а не внутри блока: при object-fit: contain блок может быть больше
  // видео, и отсчёт от блока даёт систематическую ошибку угла
  function eyePoint() {
    var r = box.getBoundingClientRect();
    var vw, vh;
    if (r.width / r.height > AR) { vh = r.height; vw = vh * AR; }
    else                         { vw = r.width;  vh = vw / AR; }
    return {
      x: r.left + (r.width  - vw) / 2 + vw * 0.482,
      y: r.top  + (r.height - vh) / 2 + vh * 0.184
    };
  }

  var still = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
  var canHover = window.matchMedia('(hover: hover)').matches;

  // на тач-устройствах курсора нет — крутим дорожку в цикле
  if (!canHover || still) {
    video.loop = true;
    video.play().catch(function () {});
    return;
  }

  video.pause();

  var target = NEUTRAL;
  var current = NEUTRAL;
  var last = 0;
  var lastSeek = -1;

  video.addEventListener('loadedmetadata', function () {
    video.currentTime = 0;
  }, { once: true });

  window.addEventListener('mousemove', function (e) {
    var p = eyePoint();
    var deg = Math.atan2(e.clientY - p.y, e.clientX - p.x) * 180 / Math.PI;
    if (deg < 0) deg += 360;
    target = angleToPos(deg);
  }, { passive: true });

  function loop(now) {
    // шаг сглаживания считаем от реального времени кадра, а не от его номера:
    // иначе на 120 Гц голова догоняет курсор вдвое быстрее, чем на 60 Гц,
    // а при просадке кадров — рывками
    var dt = last ? Math.min((now - last) / 1000, 0.1) : 1 / 60;
    last = now;
    var k = 1 - Math.pow(1 - EASE, dt * 60);

    // кратчайшая дуга: оба конца дорожки — одна и та же нейтральная
    // поза, поэтому переход через край непрерывен. Не убирать.
    var diff = target - current;
    if (diff > 0.5) diff -= 1;
    if (diff < -0.5) diff += 1;
    current = (current + diff * k + 1) % 1;

    if (video.readyState >= 1) {
      var t = current * DURATION;
      // не дёргать currentTime, пока голова стоит: лишние перемотки
      // заставляют браузер пересобирать кадр и дают микрорывки
      if (isFinite(t) && Math.abs(t - lastSeek) >= STEP) {
        lastSeek = t;
        video.currentTime = Math.min(DURATION - 0.001, Math.max(0, t));
      }
    }

    requestAnimationFrame(loop);
  }
  requestAnimationFrame(loop);
})();
```

## Настройка после запуска

| Симптом | Что менять |
|---|---|
| Догоняет слишком вяло | `EASE` увеличить до 0.15–0.2 |
| Догоняет слишком резко, хочется мягче | `EASE` уменьшить до 0.06 |
| Всё ещё видны ступеньки при медленном движении | `STEP` уменьшить до `1/192` |
| Взгляд систематически не доходит по всей дуге | левая колонка `MAP` — сдвинуть все углы на одну величину |
| Промах в одном секторе | соседние узлы `MAP` для этого сектора |
| Промах зависит от близости курсора к аватару | `0.482` и `0.184` в `eyePoint()` |

Менять по одному значению за раз.

## Что в дорожке есть по-честному, а что нет

- **Есть:** вправо, вверх-вправо, вниз-вправо, вниз, вниз-влево, влево, вверх-влево.
- **Нет:** сектор 245°–313°, то есть верх. Там нейтраль.
- **Моргание** в районе 5°–18° (курсор чуть ниже-правее лица) — в исходнике там
  закрытые глаза. Читается как обычное моргание, специально не чинится.

## Проверка перед сдачей

1. Прямоугольника видео не видно ни в одном кадре — фон шапки и фон видео совпадают
2. Курсор строго слева от лица → профиль влево
3. Курсор строго снизу → голова опущена
4. Курсор строго справа → голова повёрнута вправо, глаза открыты
5. Курсор строго сверху → персонаж плавно уходит в нейтраль, без рывка
6. Медленно провести курсором по кругу вокруг аватара — голова идёт за ним
   ровно, без ступенек и без разворотов «через всю голову»
7. Медленно сжать окно от широкого до узкого — вёрстка не ломается
8. На узком экране колонки встают в стопку, аватар сверху
9. На телефоне дорожка крутится сама по себе в цикле

## Чего делать не нужно

- Не вшивать mp4 в HTML как `data:` URI
- Не ставить `autoplay` и `loop` на десктопе
- Не пережимать `avatar-orbit-v7.mp4` — в нём уплотнены keyframe, перекрашен и
  откалиброван под браузер фон и достроены промежуточные кадры
- Не менять `--hero-bg`: фон видео подогнан именно под `#3D84A8`
- Не «дополнять» `MAP` значениями для верхнего сектора — их в дорожке нет
- Не убирать кратчайшую дугу из `loop()`
- Не убирать разворот `if (u < 245) u += 360`
- Не возвращать сглаживание к постоянному шагу — привязка к `dt` тут не украшение
- Не пересчитывать `MAP` формулой
- Не считать точку отсчёта от `getBoundingClientRect()` напрямую — только через `eyePoint()`
- Не менять `aspect-ratio`
- Не накладывать текст поверх аватара — фон видео непрозрачный
