# Блок «Гигантская девушка» — скролл-вставка

Новый секция-аттракцион между блоками. Видео управляется скроллом: пользователь
крутит колесо — камера едет по героине вверх и заканчивает видом сверху.

## Файлы

| файл | куда |
|---|---|
| `giant.mp4` | `public/video/giant.mp4` |
| `giant-mobile.mp4` | `public/video/giant-mobile.mp4` |
| `giant-poster.webp` | `public/img/giant-poster.webp` |

11,2 с · 1920×1080 · 60 fps · 13,8 МБ. Ключевые кадры каждые 10 —
это обязательное условие для перемотки скроллом, иначе перемотка дёргается.

## Разметка

Секция **не** карточка на подложке. Она во всю ширину экрана, без `--gap`,
без `border-radius` — это разрыв в ритме карточек, на нём и держится эффект.

```html
<section class="giant" aria-label="AI-визуализация: гигантская героиня в городе">
  <div class="giant__stage">
    <video class="giant__video"
           poster="/img/giant-poster.webp"
           muted playsinline preload="auto"
           data-src-hd="/video/giant.mp4"
           data-src-sd="/video/giant-mobile.mp4"></video>
  </div>
</section>
```

Без `autoplay`, без `loop`, без `controls`. Временем управляет JS.

## CSS

```css
.giant {
  position: relative;
  height: 260vh;              /* длина проезда: чем больше, тем медленнее */
  margin: 0;
  background: var(--ground);
}
.giant__stage {
  position: sticky; top: 0;
  height: 100svh;
  overflow: hidden;
}
.giant__video {
  width: 100%; height: 100%;
  object-fit: cover;
  display: block;
}

/* на мобильных скролл-скраб работает плохо — там обычный луп */
@media (max-width: 767px) {
  .giant { height: 100svh; }
  .giant__stage { height: 100svh; }
}

@media (prefers-reduced-motion: reduce) {
  .giant { height: 100svh; }
  .giant__video { display: none; }
  .giant__stage {
    background: url("/img/giant-poster.webp") center / cover no-repeat;
  }
}
```

`260vh` — управляющий параметр. Меньше — проезд быстрее и резче, больше —
медленнее. Ниже 200vh не опускать: скролл станет слишком чувствительным.

## JS

```js
(() => {
  const section = document.querySelector('.giant');
  const video   = document.querySelector('.giant__video');
  if (!section || !video) return;

  const reduce = matchMedia('(prefers-reduced-motion: reduce)').matches;
  if (reduce) return;

  const isMobile = matchMedia('(max-width: 767px)').matches;
  const px = window.innerWidth * (window.devicePixelRatio || 1);
  video.src = video.dataset[(!isMobile && px > 1400) ? 'srcHd' : 'srcSd'];

  // Мобильные: обычный луп, без перемотки
  if (isMobile) {
    video.loop = true;
    video.play().catch(() => {});
    return;
  }

  let target = 0, current = 0, raf = null, ready = false;

  video.addEventListener('loadedmetadata', () => { ready = true; tick(); });

  function progress() {
    const r = section.getBoundingClientRect();
    const total = section.offsetHeight - window.innerHeight;
    if (total <= 0) return 0;
    return Math.min(1, Math.max(0, -r.top / total));
  }

  function tick() {
    if (!ready) return;
    target = progress() * (video.duration || 0);
    current += (target - current) * 0.12;           // сглаживание
    if (Math.abs(target - current) > 1 / 60) {
      video.currentTime = current;
      raf = requestAnimationFrame(tick);
    } else {
      video.currentTime = target;
      current = target;
      raf = null;
    }
  }

  addEventListener('scroll', () => { if (!raf) raf = requestAnimationFrame(tick); },
                   { passive: true });
  addEventListener('resize', () => { if (!raf) raf = requestAnimationFrame(tick); },
                   { passive: true });
})();
```

Что здесь важно и почему:

- **Сглаживание через lerp 0.12.** Без него `currentTime` прыгает на каждое
  событие скролла и картинка дёргается. С ним камера догоняет палец плавно.
- **Порог `1/60`.** Ниже него перемотка бессмысленна — кадр тот же, а декодер
  каждый раз дёргается.
- **rAF, а не прямая запись в обработчике скролла.** Скролл сыпет событиями
  чаще кадров, декодер за ними не успевает.
- **`{ passive: true }`.** Иначе браузер считает обработчик блокирующим и
  тормозит сам скролл.

## Мобильные

Перемотка `currentTime` на iOS ненадёжна: Safari подгружает сегменты и
отдаёт кадр с задержкой. Поэтому там просто зацикленный луп на облегчённом
файле. Это не компромисс ради лени — скролл-скраб на телефоне выглядит хуже,
чем честный луп.

## Текста поверх нет

Заголовки и подписи на этот блок не ставим: кадр меняется на всю высоту
проезда, любой текст будет уезжать из-под себя. Если очень нужна строка —
только в самом конце, когда камера встала, и с появлением по прогрессу > 0,9.

## Куда в порядке страницы

Между блоками, примерно в середине страницы, где внимание проседает.
Порядок: шапка → карточки → **скролл-вставка** → остальные карточки → контакты.

Один аттракцион на сайт. Второй такой же блок обесценит первый.

## Чек-лист

1. Видео грузится: в Network есть запрос `giant.mp4` и он 200.
2. При скролле кадр меняется плавно, без рывков и без чёрных вспышек.
3. В самом верху блока — первый кадр, в самом низу — последний. Не наоборот.
4. Блок занимает всю ширину, без отступов и скругления, в отличие от карточек.
5. На ширине < 768 px видео просто циклится, перемотки нет.
6. При `prefers-reduced-motion` видео не грузится вообще, виден постер.
7. Обработчик скролла не блокирует страницу: скролл на слабом ноутбуке
   остаётся плавным даже вне блока.
8. `autoplay` и `loop` в разметке отсутствуют — на десктопе временем
   управляет только JS.
