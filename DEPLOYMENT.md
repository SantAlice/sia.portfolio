# Размещение anastasia.pics

Сайт статический: Node.js, база данных и Docker ему не нужны.
Для сервера с 1 ГБ RAM достаточно существующего веб-сервера.

## Текущее состояние — 10 октября 2026

Сайт установлен через GitHub Actions в отдельный каталог
`/var/www/anastasia.pics/releases/`; `current` указывает на опубликованный релиз.
Для него добавлен отдельный хост `/etc/nginx/sites-available/zz-anastasia.pics`.
Nginx проверен командой `nginx -t` и перечитан через reload.

Конфигурации Nginx двух существующих сайтов — `aaautomation.space` и
`vancelot3d.space` — и контрольные суммы их HTTP-ответов совпали до и после размещения.
Пароль отсутствует в коде и передаётся через зашифрованный Actions secret.
SSH-ключ сервера закреплён по отпечатку успешного первого подключения.

DNS доменов `anastasia.pics` и `www.anastasia.pics` пока не настроен.
Релиз установлен для HTTP-хоста, но публичная ссылка на собственном домене и HTTPS
ещё не готовы. После добавления A-записей нужно повторить операцию `deploy`:
она выпустит отдельный сертификат Certbot и включит редиректы на HTTPS без www.
Счётчики аналитики выключены до получения ID из аккаунтов владельца.

Прямое подключение из облачной среды отклоняется; доступ из GitHub Actions работает.

## Проверить доступ

В панели хостинга убедитесь, что сервер включён и публичный IP совпадает.
Откройте веб-консоль и выполните команды, которые ничего не изменяют:

```sh
ss -lntp
systemctl status ssh --no-pager
df -h /
```

Вывод первой команды покажет SSH-порт и порты веб-сервера. Если SSH слушает
нестандартный порт, при подключении используется `ssh -p НОМЕР_ПОРТА root@135.106.163.207`.
Не отключайте целиком firewall и не перезапускайте существующие сайты для этой проверки.

## Проверить существующее размещение

До изменений нужно определить, кто обслуживает сайты: Nginx, Apache, Caddy,
контейнеры или панель управления. Проверить домены, корни сайтов, свободное место,
настройки HTTPS и контрольные суммы существующих конфигураций.

Если работает Nginx, для нового сайта подготовлен пример
`deploy/nginx-anastasia.pics.conf`. Его нельзя применять вслепую поверх
существующего `nginx.conf`, default-host или конфигурации панели.

## DNS домена

В панели управления DNS **этого домена**:

| Имя | Тип | Значение |
| --- | --- | --- |
| `@` | A | `135.106.163.207` |
| `www` | A | `135.106.163.207` |

Это предполагает, что указанный IP подтвердился и сервер доступен извне.
Не меняйте записи двух других доменов, MX-записи почты и остальные записи.
Если у anastasia.pics есть AAAA-запись, её адрес тоже должен вести на этот сервер;
иначе часть посетителей будет попадать на другой узел по IPv6.

## Изолированный релиз

Локально собрать архив только публичных файлов:

```sh
python3 scripts/build-release.py /tmp/anastasia-release.tar.gz
```

В архив войдут `index.html`, `css/`, `js/`, `public/`, `robots.txt`,
`sitemap.xml` и публичные настройки аналитики. Исходные ZIP/MOV, `.git`,
инструкции, скрипты размещения и секреты не включаются.

После проверки сервера предлагается отдельная структура:

```text
/var/www/anastasia.pics/
  releases/<идентификатор-релиза>/
  current -> releases/<идентификатор-релиза>/
```

Новый каталог и конфигурация должны быть свободны и не использоваться другими
сайтами. Переключение `current` позволит вернуть предыдущий релиз, не затрагивая
другие каталоги. Перед перезагрузкой Nginx обязательна проверка `nginx -t`.
Используется reload, а не остановка сервиса.

## HTTPS и канонический домен

После доступности HTTP и правильного DNS выпустить сертификат Let's Encrypt для
`anastasia.pics` и `www.anastasia.pics` имеющимся на сервере способом. Проверить
автоматическое продление. Не заменять сертификаты других сайтов.

Целевой адрес сайта — `https://anastasia.pics/`.
HTTP и www должны перенаправлять на него с постоянным редиректом.
В коде уже подготовлены соответствующие canonical, Open Graph, robots.txt и Sitemap.

## Проверки после размещения

- Новый домен открывается по HTTPS, сертификат соответствует домену.
- Оба существующих сайта продолжают отвечать как до изменений;
  их конфигурации и файлы не изменились.
- `/robots.txt`, `/sitemap.xml` и медиа доступны без авторизации.
- Видео поддерживает Range-запросы; мобильные кадры загружаются и меняются по скроллу.
- Все Telegram-кнопки ведут по правильным адресам.
- HTTP и www перенаправляются на HTTPS без www.
- После записи счётчиков посещения и Telegram-события появляются в аналитике.

Порядок создания счётчиков и подтверждения сайта:
[SEARCH-AND-ANALYTICS.md](SEARCH-AND-ANALYTICS.md).

## Проверка через GitHub Actions

В репозитории добавлен workflow `Inspect and deploy anastasia.pics`.
Доступны операции:

- `inspect` — прочитать сведения о сервере и DNS;
- `deploy` — собрать и разместить отдельный релиз, проверить существующие сайты;
  при готовом DNS выпустить HTTPS-сертификат;
- `verify` — проверить HTML, SEO-файлы, мобильные кадры и Range-запросы видео
  без изменения конфигурации.

Пароль передаётся только через Actions secret `ANASTASIA_DEPLOY_PASSWORD`.
Интеграция не имеет прав управлять секретами: добавить его должен владелец
в [настройках репозитория](https://github.com/SantAlice/sia.portfolio/settings/secrets/actions).

После завершения работ удалите этот временный секрет там же кнопкой корзины
и смените пароль сервера, как планировали. Не вставляйте пароль в код workflow.
