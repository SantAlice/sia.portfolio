# Аватар в шапке — дорожка v2

Заменяет все предыдущие задания по аватару целиком. Проект — статический сайт (`index.html`, `css/`, `js/`), не React. Весь код ниже — ванильный JS и CSS.

---

## Файлы

Положить в `public/`:

- `avatar-orbit-v2.mp4` — дорожка
- `avatar-poster-v2.jpg` — постер

Имена новые намеренно: браузер не подхватит старый файл из кеша. Старые `avatar-orbit.mp4` и `avatar-poster.jpg` можно удалить после того, как новая версия заработает.

| Параметр | Значение |
|---|---|
| Разрешение | 720 × 1222 |
| Длительность | ровно 8.8 секунды, 264 кадра, 30 fps |
| Пропорция | `720 / 1222` ≈ 0.589 |
| Цвет фона | **`#499AC8`** |
| Keyframe | каждые 5 кадров |
| Звук | отсутствует |

---

## Что это такое

Это не обычное видео. Оно никогда не проигрывается: позиция воспроизведения (`currentTime`) вручную привязывается к направлению от лица персонажа к курсору мыши. На дорожке персонаж обводит взглядом полный круг, и, перематывая её, мы заставляем его смотреть в нужную сторону.

Расстояние от курсора до аватара не учитывается — важно только направление.

---

## Цвет фона шапки — критично

Фон секции шапки обязан быть точно **`#499AC8`** — тем же, что зашит в видео. При совпадении прямоугольник видео растворяется, и персонаж выглядит стоящим прямо на фоне шапки. При расхождении даже на пару тонов по краю пойдёт видимый шов.

```css
.hero{ background: #499AC8; }
```

Никакого градиента под аватаром. Если по шапке нужен градиент — он должен начинаться в стороне от блока с аватаром.

Фон внутри самого видео выровнен покадрово, «дыхания» цвета по ходу дорожки нет.

---

## Расположение

- **Текст слева, аватар справа**
- Ширина блока аватара: `clamp(220px, 26vw, 420px)`
- Пропорция блока строго `aspect-ratio: 720 / 1222`
- Между колонками зазор `clamp(24px, 4vw, 56px)`
- Вертикальное выравнивание по центру
- Текст не должен заходить на аватар: у видео непрозрачный фон, наложения не получится

В состоянии покоя персонаж смотрит влево, в сторону текста.

}

.hero__avatar video{
  width: 100%;
  height: 100%;

@media (max-width: 860px){
  .hero{
    grid-template-columns: 1fr;

  }

Про `minmax(0, 380px)`: ноль в первом аргументе обязателен. Без него колонка не сможет ужиматься и вытолкнет соседа за край экрана на узких окнах.

## JS

```js
(function () {
  var box = document.getElementById('avatarBox');
  var video = document.getElementById('avatarVideo');
  if (!box || !video) return;

  var DURATION = 8.8;   // длительность дорожки, секунды
  var EASE = 0.1;       // инерция: меньше — взгляд догоняет ленивее

  // Направление взгляда в градусах -> позиция на дорожке 0..1.
  // Градусы экранные: 0 вправо, 90 вниз, 180 влево, 270 вверх.
  // Углы идут строго по убыванию — на дорожке голова обходит круг
  // против часовой стрелки. Значения сняты покадрово с готового файла,
  // не выводить формулой и не «упрощать»: скорость движения по кругу
  // неравномерная, от 25 до 58 градусов в секунду.
  var MAP = [
    [ 315, 0.0000 ],
    [ 292, 0.1136 ],
    [ 270, 0.2068 ],
    [ 225, 0.4034 ],
    [ 180, 0.5114 ],
    [ 135, 0.6307 ],
    [  90, 0.7386 ],
    [  45, 0.8409 ],
    [   0, 0.9148 ],
    [ -42, 1.0000 ]
  ];

  var HI = 315, LO = -42;
  var REST = 0.5114;    // взгляд влево — состояние покоя

  function angleToPos(deg) {
    if (deg >= HI) deg -= 360;          // приводим к диапазону таблицы
    if (deg > HI) deg = HI;
    if (deg < LO) deg = LO;
    for (var i = 0; i < MAP.length - 1; i++) {
      var a = MAP[i], b = MAP[i + 1];
      if (deg <= a[0] && deg >= b[0]) {
        return a[1] + (b[1] - a[1]) * ((a[0] - deg) / (a[0] - b[0]));
      }
    }
    return REST;
  }

  var still = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
  var canHover = window.matchMedia('(hover: hover)').matches;

  // на тач-устройствах курсора нет — просто крутим дорожку в цикле
  if (!canHover || still) {
    video.loop = true;
    video.play().catch(function () {});
    return;
  }

  video.pause();

  var target = REST;
  var current = REST;

  video.addEventListener('loadedmetadata', function () {
    video.currentTime = REST * DURATION;
  }, { once: true });

  window.addEventListener('mousemove', function (e) {
    var r = box.getBoundingClientRect();
    var cx = r.left + r.width * 0.53;    // центр головы по горизонтали
    var cy = r.top + r.height * 0.22;    // уровень глаз

    var deg = Math.atan2(e.clientY - cy, e.clientX - cx) * 180 / Math.PI;
    if (deg < 0) deg += 360;
    target = angleToPos(deg);
  }, { passive: true });

  function loop() {
    // идём к цели по кратчайшей дуге: из 0.95 в 0.05 короче через край,
    // а не назад через всю ленту
    var diff = target - current;
    if (diff > 0.5) diff -= 1;
    if (diff < -0.5) diff += 1;
    current = (current + diff * EASE + 1) % 1;

    if (video.readyState >= 1) {
      var t = current * DURATION;
      if (isFinite(t)) {
        video.currentTime = Math.min(DURATION - 0.001, Math.max(0, t));
      }
    }

    requestAnimationFrame(loop);
  }
  requestAnimationFrame(loop);
})();
```

## Известное ограничение

Дорожка не замкнута попиксельно: первый и последний кадр — две отдельные отрисовки одной позы, они различаются волосами, фактурой вельвета и бликами. Это свойство генеративного видео, а не ошибка сборки.

Поэтому при пересечении курсором направления «вверх-вправо» относительно лица персонажа виден **скачок длиной в один кадр**. Так и должно быть. Кратчайшая дуга в `loop()` специально оставлена: без неё дельта считается в обход, и вместо скачка голова делает полный оборот — это гораздо хуже.

Сшить стык пробовали кроссфейдом и морфингом по оптическому потоку — оба дают видимое двоение лица, потому что смещения между кадрами нет (медиана оптического потока в области головы — 0.4 пикселя), модель просто перерисовала голову заново. Не тратить на это время.

## Настройка после запуска

| Симптом | Что менять |
|---|---|
| Взгляд систематически не доходит по всем четырём точкам | правая колонка `MAP` — сдвинуть все значения на одну величину |
| Промах только в одном секторе | узел `MAP` для этого сектора |
| Промах зависит от близости курсора к аватару | `0.53` и `0.22` в расчёте `cx` / `cy` |
| Догоняет слишком резко | `EASE` уменьшить до 0.06 |
| Догоняет слишком вяло | `EASE` увеличить до 0.18 |

Менять по одному значению за раз.

---

## Проверка перед сдачей

1. Курсор строго справа от лица → поворот вправо
2. Курсор строго снизу → голова опущена вниз
3. Курсор строго слева → полный профиль влево
4. Курсор строго сверху → голова запрокинута вверх
5. Границ прямоугольника видео не видно ни в одном кадре, персонаж сливается с фоном шапки
6. При пересечении направления «вверх-вправо» — короткий скачок на один кадр, но **не** полный оборот головы
7. Медленно сжать окно от широкого до узкого — вёрстка не ломается ни на одной ширине
8. На узком экране колонки встают в стопку, аватар сверху
9. На телефоне дорожка крутится сама по себе в цикле
10. При быстром движении мыши видео не тормозит и не рассыпается

## Чего делать не нужно

- Не ставить `autoplay` и `loop` на десктопе — видео управляется скриптом
- Не пережимать `avatar-orbit-v2.mp4` — в нём уплотнены keyframe и выровнен фон, обычное сжатие сломает и то и другое
- Не убирать кратчайшую дугу из `loop()` — без неё голова делает полный оборот
- Не пересчитывать `MAP` формулой — значения сняты покадрово
- Не менять `aspect-ratio` — пропорция должна совпадать с видео, иначе `object-fit` даст поля другого оттенка
- Не задавать `min-height: 100vh` для `.hero` — при узком и низком окне контент полезет наружу
- Не накладывать текст поверх аватара — фон видео непрозрачный
